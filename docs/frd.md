## ⓪ 범위 요약

- **필수 기능 수**: 37개 (하위 기능 기준). 부가 1개, 제외 2개.
- **예상 개발 작업 규모(대략)**: 화면 2개(코스 목록, 코스 상세)와 두 화면 공통 하단 안내, 데이터 파일 3개. 서버·로그인·결제·실시간 연동·사용자 입력이 없다. 필수 37개 중 상당수는 새 코드 덩어리가 아니라 "무엇을 어떤 조건에서 보여줄지" 정한 표시 규칙이다. 실제 작업에는 처음 세팅, 데이터 채우기, 마무리 점검이 더해진다.
- **복잡도를 높이는 요인**: 코드가 아니라 콘텐츠다. 스팟 5곳의 주차장 7곳과 시설 12곳 안팎의 운영시간·정기휴무·공식 링크를 공식 자료로 확인하는 일, 사진 15~20장을 고르고 출처·저작자·라이선스를 적는 일, 방문자 시점 약도를 그리는 일이 가장 큰 덩어리다. 작업 가능 시간이 화·목 14시 이후와 수요일 종일로 제한된다.
- **줄인다면 이 순서로** (삭제가 아니라 부가로 미루기. 2026-09-18 학습자는 "이대로 37개 진행"을 택했고, 아래는 일정이 밀릴 때 쓰는 예비 카드다)
  1. `F1.2` 코스 요약 목록 5줄 → 부가. 빼면 화면을 열자마자 스크롤 없이 코스 5개 이름을 보는 기능이 사라진다. 바로 아래 코스 카드 5장에 같은 정보가 있어 서비스 흐름은 끊기지 않는다.
  2. `F3.10` 줄별 썸네일 사진 → 부가. 빼면 주차장·시설을 사진으로 알아보는 단서가 없어지고 글로만 읽는다. 스팟 대표 사진 5장은 남는다. 준비할 사진이 15~20장에서 5장으로 준다.
  3. `F3.8` 약도 이미지 → 그림을 그리지 않는다(구역과 탭을 다루는 코드는 유지하고 데이터만 비운다). 빼면 네이버지도가 실제 운전 감각과 다르게 보이는 문제를 보완하는 그림이 없어진다. 설봉공원 한 곳만 그리는 절충도 가능하다.

## ① 요약

이천이 낯선 미취학·저학년 아이 동반 가족이 출발 전에 여는 모바일 웹페이지다. 코스 목록 화면에서 미리 만든 코스 5개를 취향으로 걸러 고르고, 코스 상세 화면에서 스팟 카드를 펼쳐 "어느 주차장에 대면 어디로 걸어가는지", 시설의 운영시간·정기휴무·공식 페이지 링크, 직접 답사한 방문 팁, 방문자 시점 약도를 확인한다. 맨 아래 식당 부록은 영업시간을 저장하지 않고 네이버플레이스 링크로 넘긴다.

로그인·결제·서버가 없고 사용자가 값을 입력하는 칸도 없는 정적 페이지다. 화면에 나오는 모든 내용은 데이터 파일 3개에서 오며, 내용을 고치는 일은 파일을 수정해 다시 올리는 것으로 끝난다.

### 진입 화면 점검

F1~F5의 필수 기능은 모두 위 표에 진입 화면이 적혀 있다. F6은 운영자가 파일을 편집하는 작업이라 사용자 화면이 없고, F7은 두 화면 전체에 적용되는 규칙이다.

### 의존성 점검

- `F3.12` 빈 데이터 처리(필수)가 `F3.8` 약도 구역과 `F4.3` 추천 식당 목록에 의존하므로 두 기능을 표시 코드 기준으로 필수에 두었다. 이미지와 식당 목록 내용만 선택 데이터다.
- `F1.5` 필터 결과 반영(필수)은 `F1.2` 요약 목록과 `F1.4` 코스 카드에 의존하며 둘 다 필수다.
- 제외한 네이버지도 임베드에 의존하는 필수 기능은 없다. 위치 확인은 `F3.4`의 주차장별 "지도 열기" 링크가 전부 맡는다.
- 부가로 둔 `F3.13`(주차장 띠의 꺾쇠 이동)에 의존하는 필수 기능은 없다. 주차 안내는 탭을 눌러도 닿는다.

## ③ 핵심 기능 대표 시나리오

핵심 기능 2개만 적는다. 나머지 기능으로 확장하지 않는다.

### 시나리오 1. 어느 주차장에 대면 원하는 시설로 가기 쉬운지 확인 (F3)

- **시작 조건**: 코스 상세 화면이 열려 있고, 스팟 카드가 접힌 상태다. 그 스팟에 주차장이 1곳 이상 있다.
- **정상 흐름**
  1. 접힌 카드에서 스팟 대표 사진, 스팟 이름, ★ 추천 배지, 청록 띠의 추천 주차장 한 줄, 이 코스에서 가는 곳, 방문 팁 개수 배지를 본다.
  2. 카드를 누른다. 카드가 펼쳐지고 추천 주차장 띠 아래에 탭 3개가 나온다. "추천 장소"가 켜진 상태다.
  3. 주차 안내 표에서 주차장마다 한 줄씩 "주차장 이름 → 걸어서 갈 수 있는 시설 → 진입 방향"을 읽는다.
  4. 가고 싶은 주차장 줄의 "지도 열기"를 누른다. 네이버지도가 새 창에서 그 주차장 위치로 열린다.
  5. 코스 상세 창으로 돌아와 "추천 장소" 아래 시설 목록에서 운영시간·정기휴무를 읽고, 필요하면 "공식 페이지"를 눌러 임시휴관을 확인한다.
- **대표 예외**
  - 답사하지 않은 주차장이면 그 줄에 "지도 기준" 배지가 붙는다. 하단 안내에 그 뜻이 적혀 있다.
  - 방문 팁이 0개인 스팟은 "방문 팁" 탭과 배지가 아예 없다. 약도 이미지가 없으면 "약도 보기" 탭이 없다.
  - 사진이 준비되지 않은 주차장·시설 줄은 썸네일 자리 없이 글만 나온다.
  - 상시 개방 시설 중 지도 링크를 적지 않은 것은 줄 끝에 버튼이 없다.
- **완료 기준**: 사용자가 "어느 주차장에 대고 어디로 걸어야 하는지"와 "그 시설이 언제 여는지"를 카드 한 장 안에서 읽었다.
- **데이터 변화**: 없다. 읽기만 하는 화면이며 저장하는 값이 없다.
- **사용자가 보는 결과**: 펼쳐진 스팟 카드, 새 창으로 열린 네이버지도, 새 창으로 열린 시설 공식 페이지.

### 시나리오 2. 아이 취향으로 코스 고르기 (F1)

- **시작 조건**: 코스 목록 화면이 열려 있고 취향 칩 3개가 모두 꺼져 있다. 코스 5개가 다 보인다.
- **정상 흐름**
  1. 히어로 아래 "코스 5개 한눈에" 요약 줄 5개로 어떤 코스가 있는지 훑는다.
  2. "만들기" 칩을 누른다. 칩이 켜진 색으로 바뀐다.
  3. 요약 목록과 코스 카드가 만들기 코스만 남게 걸러지고, 카드 위 소제목 숫자가 "취향별 추천 코스 1개"로 바뀐다.
  4. 남은 카드를 누른다. 그 코스의 고유 주소로 이동한다.
- **대표 예외**
  - 같은 칩을 다시 누르면 필터가 꺼지고 코스 5개 전체로 돌아온다.
  - 코스 상세에서 "← 코스 목록"이나 브라우저 뒤로 가기로 돌아오면 필터가 꺼진 전체 목록이 보인다. 필터 상태를 기억하지 않는다.
- **완료 기준**: 고른 취향의 코스만 화면에 남고, 카드를 눌러 상세로 이동했다.
- **데이터 변화**: 없다. 필터는 화면에서만 동작하며 저장하지 않는다.
- **사용자가 보는 결과**: 켜진 칩, 줄어든 요약 목록과 카드, 바뀐 소제목 숫자.

## ④ 데이터별 CRUD 표

CRUD는 Create·Read·Update·Delete, 곧 만들기·보기·고치기·지우기를 뜻한다. 모든 데이터가 이 네 동작 중 무엇이 필요한지 정해야 한다.

이 서비스는 **사용자가 읽기만 하는 정적 페이지**다. 만들기·고치기·지우기는 모두 운영자가 데이터 파일을 편집해 다시 올리는 방식이며, 화면에는 그 기능이 나오지 않는다.

| 데이터 | 사용자 | 운영자 | 저장 위치 |
|---|---|---|---|
| 권역 (이름) | 보기만 | 파일 편집 | `courses.json` 안의 값 |
| 코스 (이름, 권역, 트랙, 비 오는 날, 소개, 포함 스팟, 스팟별 추천 주차장·가는 시설, 근처 식당 검색 링크) | 보기만 | 만들기·고치기·지우기 (파일 편집) | `courses.json` |
| 스팟 (이름, 한 줄 소개, 확인일, 확인 방법) | 보기만 | 만들기·고치기·지우기 (파일 편집) | `spots.json` |
| 주차장 (이름, 위치 설명, 네이버지도 링크, 갈 수 있는 시설, 진입 방향, "지도 기준" 여부) | 보기만 | 만들기·고치기·지우기 (파일 편집) | `spots.json` 안의 목록 |
| 시설 (이름, 한 줄 소개, 운영시간·정기휴무, 공식 페이지, 전화, 지도 링크) | 보기만 | 만들기·고치기·지우기 (파일 편집) | `spots.json` 안의 목록 |
| 방문 팁 (문장 한 줄, 유형 태그) | 보기만 | 만들기·지우기만 (문장 한 줄을 넣거나 뺀다. 고치기는 문장을 다시 쓰는 것과 같다) | `spots.json` 안의 목록 |
| 약도 이미지 (파일, 설명 캡션) | 보기만 | 만들기·지우기 (이미지 폴더에 넣거나 뺀다) | 이미지 폴더 + `spots.json` |
| 사진 (파일, 대체텍스트, 출처, 저작자, 라이선스, 촬영일) | 보기만 | 만들기·고치기·지우기 | 이미지 폴더 + 각 데이터 파일 |
| 식당 부록 (코스별 검색 링크, 식당 이름, 네이버플레이스 링크, 팁) | 보기만 | 만들기·고치기·지우기 (파일 편집) | `restaurants.json` |
| 바깥 링크 타일 (이름, 설명, 주소) | 보기만 | 고치기만 (2개 고정) | 데이터 파일의 값 2개 |
| 기준일 | 보기만 | 고치기만 (값 하나) | 한 곳에서만 관리 |
| 취향 필터 상태 | 화면에서 켜고 끄기 | 해당 없음 | 저장하지 않는다 |
| 스팟 카드 펼침 상태, 탭 선택 | 화면에서 바꾸기 | 해당 없음 | 저장하지 않는다 |

식당의 영업시간·휴무·메뉴·가격은 어느 동작도 없다. 서비스가 저장하지 않고 네이버플레이스 링크로 넘긴다.

## ⑤ 기능별 정책 결정표

2026-09-18 학습자가 "질문 없이 다 추천으로"를 선택해 아래를 모두 확정했다. 이 표는 4단계 기술 설계(TRD)가 그대로 이어받는 입력이다.

### 시안 대조로 정한 화면 규칙

| 결정 | 내용 | 이유 |
|---|---|---|
| "← 코스 목록" 링크 | 코스 상세 맨 위에 글자 링크를 둔다. 브라우저 뒤로 가기도 그대로 쓴다 | 시안에 있다. 화면 안 링크가 뒤로 가기보다 눈에 띈다 |
| 사진 출처 표시 | 대표 사진 위에 출처·저작자를 겹쳐 쓴다. 예: "설봉호 · Wikimedia Commons" | 자유 이용 허가(CC) 사진을 쓰려면 표기가 필요하다 |
| 전화번호 위치 | 시설의 운영시간 요약 줄 끝에 함께 적는다. 예: "10:00~18:00 · 월요일 휴관 · 문의 031-633-9734" | 시안이 정한 자리다. 줄이 늘지 않는다 |
| 개수 표시 | 소제목과 탭에 개수를 적는다. "취향별 추천 코스 5개", "추천 장소 6", "방문 팁 3" | 펼치기 전에 분량을 가늠하게 한다 |
| "추천 장소 N"의 N | 그 스팟의 전체 시설 수. 이 코스에서 가는 시설 수가 아니다 | 시안의 6이 설봉공원 시설 6곳이다 |
| 접기 토글 | 스팟 카드 오른쪽 위에 "접기 ∧" 글자를 둔다 | 펼친 뒤 다시 닫는 길이 필요하다 |
| 상시 개방 시설의 버튼 | 지도 링크를 적은 시설에만 "지도 열기"를 붙이고, 안 적은 시설은 버튼 없이 한 줄 소개만 둔다 | 시안에서 놀이터·조각공원엔 버튼이 있고 호수 산책엔 없다 |
| 취향 필터 적용 범위 | 코스 카드와 "코스 5개 한눈에" 요약 줄을 함께 거르고 소제목 숫자도 바꾼다 | 한 화면에 두 목록이 서로 다르게 보이면 헷갈린다 |
| "지도 기준" 표기 | 화면 배지는 짧게 "지도 기준", 뜻풀이는 하단 안내에만 둔다 | 카드 안 문장이 길어지는 것을 막는다 |
| 없는 코스 주소 | 코스 목록으로 보낸다 | 빈 화면을 막는다 |
| 스팟 카드 2개 동시 펼치기 | 둘 다 열어 둘 수 있다. 하나를 열면 다른 하나가 닫히는 방식이 아니다 | 남부 만들기 코스는 두 곳의 주차장을 비교하게 된다 |
| 권역 소개 3줄 | 넣지 않는다 | 코스 요약 줄과 카드마다 권역 이름이 이미 붙어 있어 같은 말이 세 번 나온다 |
| 하단 안내 줄 수 | 서비스 소개, 기준일, "지도 기준" 뜻, 모두 3줄 | 기준일 줄이 이미 "공식 페이지에서 확인" 안내를 한다 |

### 범위와 일정

| 결정 | 내용 | 이유 |
|---|---|---|
| 네이버지도 임베드 | **넣지 않는다.** 코스 목록의 지도 상자도 함께 뺀다 | PRD가 정한 포함 조건 "2026-09-16(수) 오전 30분 안에 키 발급"이 지났고 키를 받지 않았다. PRD의 자기 규칙을 따른다. 키를 나중에 받으면 같은 자리에 다시 넣을 수 있다 |
| 구현 완성 목표일 | 2026-09-23(수) | 작업 가능 시간이 화·목 14시 이후와 수요일 종일이다. 09-18(금) 문서 3~5단계, 09-22(화) 오후 구현 시작, 09-23(수) 종일 구현과 데이터 |
| 배포 목표일 | 2026-09-24(목) | 09-24(목) 오후에 점검하고 올린다 |
| 축소 후보 적용 여부 | 적용하지 않는다. 필수 37개 그대로 간다 | 화면 2개짜리 정적 페이지라 코드는 감당 가능하고, 줄여서 아끼는 것은 주로 데이터 작성 시간이다. 일정이 밀리면 ⓪절의 순서대로 뺀다 |

### 화면 동작

| 결정 | 내용 | 이유 |
|---|---|---|
| 필터 상태 기억 | 기억하지 않는다. 상세에 갔다 돌아오면 코스 5장 전체가 보인다 | 동작이 하나뿐이라 예측하기 쉽다. 코스가 5개뿐이라 다시 누르는 부담이 작다 |
| 스팟 카드 기본 상태 | 접힘 | 펼치지 않고도 추천 주차장 한 줄이 보이는 것이 PRD의 성공 기준이다 |
| 탭 기본 선택 | "추천 장소" | 주차 안내와 시설 정보가 이 서비스의 핵심이다 |
| 사진이 없을 때 | 회색 빈 상자를 남기지 않고 사진 자리를 통째로 숨긴다 | 빈 상자는 "사진이 안 떴다"는 오해를 준다 |
| 이름이 확인 안 된 주차장·시설 | 그 줄을 비워 두지 않고 통째로 뺀다. 남부 코스 두 개는 "안내센터 옆 주차장" 한 줄만 둔다 | 지어낸 이름을 쓰지 않는다는 PRD의 데이터 사용 원칙을 따른다 |

### 4단계 기술 설계로 넘기는 것

- 코스별 고유 주소를 만드는 방식 (파일을 코스마다 나눌지, 한 파일에서 주소 뒷부분으로 나눌지)
- 데이터 파일을 화면에 불러오는 방식
- 배포 위치와 방법 (GitHub Pages가 자연스럽다)
- 데이터 문법 검사를 언제 어떻게 돌릴지

## ⑥ 숨은 기능 목록

화면에 버튼으로 보이지 않지만 없으면 서비스가 제대로 돌아가지 않는 것들이다.

- `F2.5` 없는 코스 주소로 들어왔을 때 코스 목록으로 보내기
- `F3.12` 팁이 0개거나 약도가 없을 때 탭과 구역을 숨기기
- `F4.3` 식당 목록이 비었을 때 구역 숨기기
- `F6.2` 기준일을 한 곳에서만 고치기
- `F6.3` 사진의 출처·저작자·라이선스 기록 — 남의 사진을 쓰기 위한 법적 요건이다
- `F6.4` 배포 전 데이터 문법 검사
- `F6.5` 네이버지도 검색 링크 자동 생성

## ⑦ 표준 적용 항목

학습자에게 고르게 하지 않고 자동으로 넣는 것들이다. 구체적인 구현 방식은 4단계 기술 설계에서 정한다.

- **바깥 링크는 새 창으로 열고 안전 속성을 붙인다** — 새로 열린 페이지가 원래 페이지를 조작하지 못하게 막는 표준 설정이다.
- **모든 사진에 대체텍스트를 넣는다** — 사진이 안 뜨거나 화면을 소리로 읽어 주는 기기를 쓸 때 무엇인지 알 수 있게 한다.
- **데이터 파일의 글자를 화면에 넣을 때 특수문자를 안전하게 바꾼다** — 따옴표나 꺾쇠가 화면 구조를 깨뜨리지 않게 한다.
- **로그인·개인정보 수집이 없다** — 사용자가 입력하는 칸이 없으므로 비밀번호 저장, 로그인 유지, 입력값 검증 같은 항목은 해당하지 않는다.
- **누르는 영역은 높이 44px 이상으로 둔다** — 아이를 안고 한 손으로 쓰는 상황에서 잘못 눌리지 않게 한다.

## ⑧ 공통 동작 규칙

- 사용자가 값을 입력하는 칸이 없으므로 입력 검증과 오류 메시지 화면이 없다. 그 자리를 **데이터가 비었을 때의 규칙**이 대신한다. 값이 없으면 그 줄·구역·탭을 숨기고, 빈 칸이나 "정보 없음" 같은 글자를 남기지 않는다.
- 모든 바깥 링크는 새 창으로 연다. 화면 안에서 이동하는 링크("← 코스 목록", 코스 카드, 요약 줄)만 같은 창에서 움직인다.
- 권한 등급이 없다. 모든 방문자가 같은 화면을 본다.
- 답사하지 않은 주차·진입 정보에는 예외 없이 "지도 기준" 배지를 붙인다.
- 공식 페이지가 있는 시설에는 예외 없이 링크를 붙인다.
- 화면에 나오는 모든 글은 데이터 파일에서 온다. 글을 고치려고 화면 코드를 건드리지 않는다.

## ⑨ 인수 기준

만든 뒤 눈으로 확인하는 항목이다. 전부 통과하면 이 단계의 기능이 다 들어간 것이다.

**코스 목록 화면**

1. 페이지를 열면 맨 위에 진초록 블록과 "이천 아이맵"이 보이고, 그 아래 코스 이름 5줄이 스크롤 없이 보인다.
2. "만들기" 칩을 누르면 요약 줄과 카드가 만들기 코스만 남고, 소제목 숫자가 "1개"로 바뀐다. 같은 칩을 다시 누르면 5개 전체로 돌아온다.
3. 코스 카드 5장이 모두 보이고, 각 카드에 코스 이름·취향 트랙·권역·스팟과 추천 주차장 한 줄이 있다.
4. 맨 아래 타일 2개를 누르면 이천시 공식 블로그와 이천관광 누리집이 새 창에서 열린다.
5. 지도 상자는 화면에 없다.

**코스 상세 화면**

6. 코스 카드를 누르면 그 코스만의 주소로 이동한다. 주소를 복사해 다른 기기에서 열면 같은 코스가 나온다.
7. 맨 위 "← 코스 목록"을 누르면 목록으로 돌아가고, 돌아간 목록은 코스 5장 전체를 보여준다.
8. 없는 코스 주소를 주소창에 직접 넣으면 빈 화면이 아니라 코스 목록이 나온다.
9. 스팟 카드는 접힌 채로 나오고, 펼치지 않은 상태에서도 이 코스의 추천 주차장 한 줄이 읽힌다.
10. 카드를 누르면 펼쳐지고 탭 3개가 나온다. "추천 장소"가 켜져 있다. 오른쪽 위 "접기 ∧"를 누르면 다시 접힌다.
11. 스팟이 2개인 코스에서 두 카드를 동시에 펼쳐 둘 수 있다.
12. 모든 주차장 줄에 "주차장 → 갈 수 있는 시설 → 진입 방향"과 "지도 열기" 버튼이 있고, 누르면 네이버지도가 새 창에서 그 위치로 열린다.
13. 공식 페이지가 있는 시설은 모두 "공식 페이지" 버튼이 있고, 누르면 새 창에서 열린다.
14. 답사하지 않은 주차·진입 정보에 "지도 기준" 배지가 빠짐없이 붙어 있다.
15. "방문 팁" 탭을 누르면 팁 문장이 목록으로 나오고, `주차:` `진입:` 같은 앞머리가 작은 태그로 바뀌어 보인다.
16. 맨 아래 "근처 식당 네이버지도에서 보기"를 누르면 네이버지도 검색 결과가 새 창에서 열린다.

**데이터가 비었을 때**

17. 팁이 0개인 스팟은 "방문 팁" 탭과 접힌 카드의 팁 배지가 아예 없다.
18. 약도 이미지가 없는 스팟은 "약도 보기" 탭이 없다.
19. 사진이 없는 스팟도 카드가 깨지지 않고, 회색 빈 상자가 남지 않는다.
20. 추천 식당 목록이 비어 있으면 "추천 식당" 구역이 통째로 안 보이고, "근처 식당 네이버지도에서 보기" 버튼은 그대로 있다.

**데이터 고치기**

21. 데이터 파일에 팁 문장 한 줄을 넣거나 빼면 화면의 배지 숫자와 목록이 바뀐다. 화면 코드는 고치지 않았다.
22. 기준일 값 하나를 바꾸면 두 화면 하단의 날짜가 함께 바뀐다.

**화면 크기**

23. 폭 390px 휴대폰 화면에서 좌우로 밀리는 부분 없이 한 열로 보인다.
24. PC 브라우저를 크게 열어도 가운데 640px 기둥으로만 보이고 좌우는 빈 배경이다.
